# Compute-scoped library set for Databricks Runtime 18 LTS
# (Spark 4.1.0, Python 3.12.3).
#
# Point a cluster's Libraries tab (or a job's `libraries` block) at this file:
#     { "requirements": "/Volumes/<catalog>/<schema>/sas_parser/requirements.txt" }
#
# DERIVED, NOT HAND-WRITTEN. Regenerate after any `uv lock` change:
#
#     uv export --frozen --no-dev --no-hashes --no-emit-project --no-annotate \
#         --no-header --extra sharepoint --extra vault --extra azure
#
# then drop every package Databricks Runtime 18 LTS already ships at a version
# the lock is happy with. What remains is this file. `constraints-dbr18.txt` beside
# it records the dropped set at its runtime version, so the result can be
# re-verified against a stock cluster without one:
#
#     uv pip compile databricks/requirements.txt \
#         -c databricks/constraints-dbr18.txt \
#         --python-version 3.12 --python-platform linux
#
# The requirements intentionally upgrade libraries whose DBR 18 versions do not
# meet the project's lock or declared floors (including pydantic and the
# LangChain/OpenAI stack). `typing-extensions` is explicit because DBR 18's
# 4.12.2 is below langchain-protocol's >=4.13 floor. The adjacent constraints
# file keeps compatible runtime-provided libraries at their stock DBR 18
# versions during verification.
#
# DELIBERATELY ABSENT --- do not add:
#   pyspark, delta-spark      DBR 18 provides Spark 4.1.0 and its built-in Delta
#                             runtime. Installing the local `spark` extra here
#                             can shadow the runtime's matched Python client.
#   databricks-sql-connector  in the `databricks` extra, but unused on a cluster:
#                             its only consumer, sql_connect_params(), builds
#                             kwargs for callers OUTSIDE a notebook and raises on
#                             a cluster.
#   databricks-sdk, msal      already satisfied by DBR 18 (0.67.0 / 1.34.0).
#   tiktoken, python-dotenv   already satisfied (0.12.0 / 1.2.1).
#
# `colorama` carries a win32 marker from the universal lock and is inert here.
